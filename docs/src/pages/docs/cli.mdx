# CLI

ministaのdev／previewコマンドはViteを基盤に動作します。`minista build`はrender environmentとclient environmentを1つのApp Build lifecycleとして実行し、静的HTMLとアセットを生成します。

通常の開発、CLI実行、testにminista自身の事前buildは必要ありません。

## Commands

|コマンド|内容|
| --- | --- |
| `minista [root]` |ModuleRunnerを使った開発モード（`Ctrl + C`で停止）|
| `minista build [root]` |App Build lifecycleによる静的書き出し|
| `minista preview [root]` |静的書き出し後の動作確認|
| `minista check [root]` |page moduleと`getStaticData()`を評価し、route／pageの問題を検査|
| `minista inspect [root]` |sourceからProject Graphの概要を表示|
| `minista explain <node-id> [root]` |指定したGraph nodeの関係を説明|

## Machine-readable commands

`check`、`inspect`、`explain`は`--json`で機械可読な結果を標準出力へ返します。diagnosticには安定した`code`、`severity`、`message`、必要に応じて`hint`、`location`、`phase`、`nodeId`が含まれます。

```sh
minista check --json
minista inspect --json
minista explain "page:route%3Asrc/pages/index.jsx#/" --json
```

`minista check`は直近の検査結果を`.minista/diagnostics.json`にも保存します。`minista build`はProject Graphとoutputの安全なprojectionを`.minista/manifest.json`へ、build diagnosticを`.minista/diagnostics.json`へ保存します。

build済みmanifestだけを読み、Vite serverやuser moduleを起動せずに確認する場合は`--manifest`を使います。

```sh
minista inspect --manifest --json
```

## Options

[ViteのCLIオプション](https://ja.vitejs.dev/guide/cli.html)はdev／build／previewへ引き渡されます。App Buildで処理できないbuild optionを指定した場合はcompatibility fallbackを使用することがあります。

|独自のオプション|対象|内容|
| --- | --- | --- |
| `--json` |`check`／`inspect`／`explain`|結果とdiagnosticをJSONで出力|
| `--manifest` |`inspect`|`.minista/manifest.json`だけを読み取る|

v4の`--oneBuild`はv5で削除されました。指定すると`MINISTA_CLI_OPTION_REMOVED`で終了するため、commandから削除してください。標準の`minista build`が1つのApp Build lifecycleを使用します。
