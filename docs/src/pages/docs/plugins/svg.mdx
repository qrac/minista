# pluginSvg

ルートパスのSVGファイルをHTMLにインラインで展開するプラグイン。

- 展開時にSVGOでコードを最適化

## Table of Contents

contents list

## v5での処理

Vite adapterがSVGの読込とSVGO最適化を行い、共有Documentの`compose` phaseでmarkerをインラインSVGへ置換します。buildとdevは同じfeatureとstructured diagnosticを使用します。

## How To Use

```js title="./minista.config.js"
import { pluginSvg } from "minista"

export default {
  plugins: [pluginSvg()],
}
```

```jsx title="./src/pages/index.jsx"
import { Svg } from "minista/assets"

export default function () {
  return <Svg src="/src/assets/square.svg" />
}
```

## Options

```js title="Default"
pluginSvg({})
```

### config

- 型: `Config`
- デフォルト: `undefined`

[svgo](https://www.npmjs.com/package/svgo)のConfigを渡して最適化処理の内容を変更できます。

## Svg

ルートパスのSVGファイルを読み込んで `<svg>` タグに展開するコンポーネント。

- 展開時にSVGOでコードを最適化

```jsx title="./src/pages/index.jsx"
import { Svg } from "minista/assets"

export default function () {
  return <Svg src="/src/assets/square.svg" />
}
```

```xml title="Dist"
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">
  <path d="M76 76h360v360H76z" style="fill:#000;stroke-width:0"></path>
</svg>
```

type SvgProps = {
  src: string

## Diagnostics

SVGの展開に失敗した場合、buildは次のstable diagnostic codeを出力します。

- `MINISTA_SVG_READ_FAILED`: SVG fileの読込失敗
- `MINISTA_SVG_OPTIMIZE_FAILED`: SVGOによる最適化失敗
- `MINISTA_SVG_PARSE_FAILED`: SVG markupの解析失敗

存在しないsourceは`MINISTA_SVG_SOURCE_NOT_FOUND` errorとなり、buildを失敗させます。project内のSVGにproject相対locationが含まれます。HTML document adapterの解析、selector、変更、serializeに失敗した場合は、対応する `MINISTA_HTML_*_FAILED` codeが出力されます。

## 属性の合成とdev更新

SVGO最適化後のルートから、`viewBox`、`preserveAspectRatio`、サイズ、`fill`／`stroke`などの描画属性、`style`／`class`を保持します。`Svg`に明示した同名propsを優先し、`style`／`className`も属性単位で置き換えます。元SVGのルート`id`、イベント属性、`data-*`などの任意属性はコピーしません。明示propsとsourceの両方にviewBoxがない場合は`0 0 0 0`を使います。

devでは参照sourceの追加・変更・削除に応じてcacheを無効化し、参照ページを再読み込みします。server間でcacheを共有せず、再buildでもsourceを読み直します。内部IDの名前空間化はこの変更に含みません。
