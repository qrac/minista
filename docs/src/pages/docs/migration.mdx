# Migration

ここではminista v4からv5への移行方法を説明します。

v3以前を利用している場合は、先に[v3→v4の移行手順（保存版）](https://github.com/qrac/minista/blob/23d6676557f241ba33141b5f8abba7fabd8bc9ff/docs/src/pages/docs/migration.mdx#v3からv4)を参照してください。

## Beautifyとimage preload

`removeImagePreload`を`pluginBeautify`から`pluginSsg`へ移します。旧optionの明示指定は`MINISTA_BEAUTIFY_OPTION_MOVED`になります。

```js
plugins: [
  pluginSsg({ removeImagePreload: false }),
  pluginBeautify(),
]
```

SSGの既定値は`true`です。以前Beautifyを使わなかったprojectも、dev／buildともにrendererのimage preloadを除去します。保持する場合は上記の`false`を指定してください。従来のbody直下限定からrenderer出力全体へ対象が変わるため、Layoutのheadへ直接書いたimage preloadは`Head` APIへ移すと保持できます。Beautifyの対象globでpreloadを制御する方法は終了します。

JS整形には`build.rolldownOptions.output.minify: false`、CSS整形には`[hash]`のない文字列の`assetFileNames`が必要です。整形対象のJS／CSSとsourcemapの併用は診断で停止します。詳しい設定例と診断は[pluginBeautify](/docs/plugins/beautify)を参照してください。

## 対応環境と基本設定

ReactとReact DOMのpeerDependenciesを`>=19.0.0`へ変更しました。React 18のサポートと専用テストを終了し、React 19を検証の基準とします。React 18を利用しているprojectは、v5への移行時に両方を19以降へ更新してください。

基本的なVite configは継続して使用できます。Bundle・MDX・Entryの公開plugin APIは以下の手順でSSGへ移してください。内部buildは、Vite CLIをrender用とclient用に2回起動する方式から、render environmentとclient environmentを単一のVite app buildで順にビルドする方式へ変更されました。

SSGへ統合されたプラグインの設定を移したうえで、commandに`--oneBuild`が残っている場合は削除してください。v5ではこのoptionを指定すると`MINISTA_CLI_OPTION_REMOVED`で終了します。

```diff
- minista build --oneBuild
+ minista build
```

v5では次の機械可読な出力とcommandを利用できます。

- `minista check [--json]`: route／pageと`getStaticData()`を検査
- `minista inspect [--json]`: sourceからProject Graphを表示
- `minista inspect --manifest [--json]`: build済みmanifestだけを表示
- `minista explain <node-id> [--json]`: Graph nodeの関係を説明

生成workspaceはrootにpackage.jsonがあれば`node_modules/.minista`、なければ`.minista`です。旧root直下snapshotは自動移動・削除・読込しません。更新後にcheck／buildで再生成してください。`minista agents --json`で保存先を取得でき、`minista agents --write`で既存projectへagent向け案内を追加できます。

- `node_modules/.minista/manifest.json`: build時のProject Graph／output projection
- `node_modules/.minista/diagnostics.json`: 直近のcheck／build diagnostic

JavaScript利用者は事前buildを必要としません。ministaのpackage entry、CLI、testは`src/`のJavaScript + JSDoc実装を直接参照します。

## TypeScriptの公開型

Island／Beautifyのoption型と`minista/client`のMD／MDX宣言の参照を修正しました。Archive／Beautifyの宣言に必要な型依存はministaと一緒にインストールされます。Reactに対応する`@types/react`／`@types/react-dom`をprojectへ追加してください。React 19で`skipLibCheck:false`で公開型を利用できます。既存のoption名や設定値に変更はありません。

## Svgの属性保持と欠落source

`pluginSvg()`はSVGO最適化後の描画用ルート属性を保持します。`fill`／`stroke`やサイズをsourceで指定している場合は出力へ反映されます。上書きする場合は`Svg`の同名propsを指定してください。`style`／`className`は属性全体を置き換えます。

存在しないsourceを黙って残す動作は廃止し、`MINISTA_SVG_SOURCE_NOT_FOUND` errorでbuildを失敗させます。`src`はproject root相対として解決されます。dev中のsource変更は再起動なしで反映されます。

## v5のArchive入力と欠落診断

`pluginArchive()`および`archives[].srcDir`の省略時は、固定の`dist`ではなく解決済み`build.outDir`を入力にします。例えば`build.outDir: "output"`なら`output`を圧縮し、既定の出力名は`output/dist.zip`です。従来どおり別の`dist`を入力にしたい場合は`srcDir: "dist"`を明示してください。

欠落した入力は空archiveの成功生成ではなく`MINISTA_ARCHIVE_SOURCE_NOT_FOUND` errorになり、ディレクトリ以外の指定は`MINISTA_ARCHIVE_SOURCE_NOT_DIRECTORY` errorになります。存在する空ディレクトリは引き続き許可します。同じ`archives`に設定された全出力パスは前回分も入力から除外し、再build時のarchiveの入れ子化を防ぎます。

## Islandの遅延module評価

`client:visible`／`client:media`／`client:idle`はhydrationだけでなく、componentのJavaScript取得とmodule評価も条件成立まで遅延します。component moduleのトップレベルにある副作用をページ初期化として利用していた場合は、即時実行するscriptへ移してください。`client:load`／`client:only`はIsland entry実行時に取得を開始します。初期表示用のSSG CSSは維持されます。

## Svg／Spriteの内部IDと重複symbol

内部IDは決定的なprefix付きに変わります。元IDへの外部CSS／JavaScript参照を避け、classや明示propsを使用してください。Spriteの公開symbol IDは維持しますが、重複は上書きせず`MINISTA_SPRITE_DUPLICATE_SYMBOL` errorになります。衝突するsymbolを改名してください。Spriteは元のルート描画属性と共有defsも保持するようになります。

## pluginBundle／pluginMdxのSSG統合

`pluginBundle()`と`pluginMdx()`をimportとplugins配列から削除し、それぞれの設定を`pluginSsg()`の`bundle`と`mdx`へ移してください。

```js title="./vite.config.js"
import { defineConfig, pluginSsg } from "minista"

export default defineConfig({
  plugins: [
    pluginSsg({
      bundle: { outName: "bundle" },
      mdx: { frontmatter: { name: "metadata" } },
    }),
  ],
})
```

MDX・Markdownはデフォルトで有効です。不要な場合は`mdx: false`を指定してください。Bundle独自の`src`は廃止したため、ページの探索範囲は`pluginSsg({ src: [...] })`へまとめます。`useExportCss`も廃止し、ページとLayoutがimportするCSSは常に出力します。CSS ModulesはHTMLを生成したrender environmentと同じ変換結果を使用します。

詳細は[pluginSsg](/docs/plugins/ssg)を参照してください。

## pluginEntryのSSG統合

v5では`pluginEntry()`を削除しました。HTMLのCSS・JavaScript・画像参照は`pluginSsg()`だけでビルドされます。importとplugins配列から`pluginEntry`を削除してください。既存の参照やViteの出力設定はそのまま利用でき、publicのCSS・JSとも併用できます。

```js title="./vite.config.js"
import { defineConfig, pluginSsg } from "minista"

export default defineConfig({ plugins: [pluginSsg()] })
```

JSがimportしたCSSへscriptのURLが誤って置換される場合と、Legacy buildでpublic CSSが重複挿入される場合も修正しました。

`pluginSsg()`の戻り値は内部Viteプラグインの配列になりました。通常の`plugins: [pluginSsg()]`は変更不要です。独自コードで戻り値を直接調べている場合は、配列を展開してから各プラグインを参照してください。

## EntryのHTML参照

SSGに統合したEntry機能の書換え対象を収集対象と同じ`link[href]`、`script[src]`、`img[src]`、`img[srcset]`、`source[srcset]`、`use[href]`へ揃えました。別の要素で収集されたURLと同じ値でも、`meta[content]`、`video[poster]`、`a[href]`などの対象外属性は変更しません。これらの属性で生成assetを使う場合は、SSGのmodule importから得たURLかpublic assetのURLを指定してください。

entryがimportするCSSは参照ページにだけ一度挿入します。別ページのentryを通じた暗黙のCSS適用に依存していた場合は、対象ページ／LayoutからCSSをimportするか、明示的なstylesheet linkを追加してください。`//`で始まる外部URLは収集せず、CDNの絶対URLを指定した`base`はprotocolを保持します。query／fragmentは保持しますが、Viteのmodule変換queryとしては解釈しません。詳細は[pluginSsgのHTMLアセット参照](/docs/plugins/ssg/#html-assets)を参照してください。
