# ministaを選ぶ理由

ministaは、Reactで制作し、HTML・CSS・JavaScriptを成果物として公開・納品したいときに適しています。制作に慣れた技術を使いながら、公開先や引き渡し先に合わせて静的ファイルを用意できます。

## 慣れた書き方で制作できる ||write-with-familiar-tools||

ページも共通パーツもJSX・TSXで記述します。Reactのコンポーネント、props、JavaScriptの式を使えるため、ページ用に別のテンプレート記法を覚える必要はありません。

TypeScriptの補完や型チェック、コードの自動整形も利用できます。本文中心のページにはMarkdown・MDXを選び、共通部分はReactコンポーネントとして再利用できます。

## 納品に合わせて出力できる ||output-for-delivery||

Webサイトの公開だけでなく、生成したHTMLやアセットを引き渡す制作にも対応します。ファイル名や出力先を調整し、HTML・CSS・JavaScriptを読みやすく整形して、ZIPにまとめられます。

既存サイトの改修や、別のシステムへHTMLを組み込む案件でも、成果物を直接確認しながら制作できます。[HTMLの整形](/ja/docs/guide/beautify)と[納品用アーカイブ](/ja/docs/guide/archive)で具体的な設定を紹介します。

## 公開先を選びやすい ||flexible-hosting||

公開先には、静的ファイルを配信できる環境を使います。静的ホスティングやCDNに加え、FTPでアップロードするレンタルサーバーでも公開できます。

公開後にNode.jsやministaのサーバーを運用する必要はありません。サイト内検索も、ビルド時に生成した検索データとブラウザ側のUIで実装できます。

## 向いているプロジェクト ||suitable-projects||

- 共通コンポーネントで複数ページを制作するコーポレートサイト
- HTMLを成果物として引き渡すLPやサービスサイト
- Markdown・MDXで本文を管理するドキュメントやブログ
- ビルド時にCMSのデータを取得するコンテンツサイト

特に、内容をビルド時に確定できるサイトや、静的ファイルの納品が必要な制作に向いています。ページの一部に操作UIが必要でも、通常のscriptやIslandを組み合わせられます。

## 別の仕組みが必要な用途 ||when-to-use-other-services||

ministaは、アクセスのたびにサーバーでページを生成する仕組みを提供しません。ログイン状態に応じたページ生成や、リクエストごとのデータ処理が中心なら、別のサーバーやAPIとの役割分担が必要です。

ビルド後の内容を更新するには、再ビルドするか、ブラウザからデータを取得します。更新頻度や認証、フォーム送信などの要件も踏まえて、公開先と必要なサービスを選びます。

設計の考え方は[理念](/ja/docs/philosophy)、導入方法は[はじめる](/ja/docs/guide/)をご覧ください。
