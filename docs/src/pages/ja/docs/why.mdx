# ministaを選ぶ理由

なぜ？「Next.jsのように書いて、Astroのように出力」したいからです。

ministaは、ReactのJSX・TSXで制作し、通常のHTML・CSS・JavaScriptとして公開・納品したいときに役立ちます。

## Table of Contents

contents list

## すべてをJSXとTypeScriptで書く

- Vue.jsのエディタサポートに苦しんだ経験はありませんか？
- Hugoのテンプレート記法に苦しんだ経験は？
- AstroのページがJSXで書けないことに不満は？

ministaは独自の言語を必要としません。JavaScript標準の文法で書くReactの恩恵を受け、シンタックスハイライト・型補完・自動整形までエディタの機能を100%活かせます。

## 納品しやすい出力

- Next.jsやGatsby.jsの独自タグが納品の邪魔になった経験は？
- Astroの出力を案件に合わせきれなかったことは？
- ViteでSSGできれば良いのにと思ったことは？

必要なのはモダンで書きやすくも、真に静的に出力できるフレームワークです。ministaは最初からレガシーなWebサイトの楽に改修したいという目的で作られました。

更に、minifyされていないフォーマッターを通した綺麗なHTML・CSS・JavaScriptを出力する機能と、ファイルをzipアーカイブとしてまとめる機能を内蔵しています。

## サーバーに依存しない出力

- Next.jsやAstroの機能が特定のサーバー依存で落胆した経験は？
- 全文検索でAlgoliaの利用をためらったことは？
- 外部連携サービスの管理コストをゼロにしたいと思ったことは？

ministaが出力したWebサイトは昔からあるレンタルサーバーにFTPで放り込むだけでも使えます。

HTMLの解析からJSONを生成しクライアントサイドのみで全文検索を実装する機能も備えています。

## 向いているプロジェクト

- 共通コンポーネントを使って複数ページを制作するコーポレートサイト
- HTMLを成果物として引き渡すランディングページやサービスサイト
- MarkdownやMDXで本文を管理するドキュメントやブログ
- ビルド時にCMSからデータを取得して公開するコンテンツサイト

ministaは、アクセスのたびにサーバーでページを生成する仕組みを提供しません。ログイン状態によるページ生成やリクエストごとのデータ処理が中心となる場合は、別のサーバーやAPIとの役割分担が必要です。ビルド後のデータ更新には再ビルド、またはブラウザからのデータ取得を使います。

設計の考え方は[理念](/ja/docs/philosophy)、具体的な導入方法は[はじめる](/ja/docs/guide/)で紹介します。
