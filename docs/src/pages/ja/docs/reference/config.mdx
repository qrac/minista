# Config

ministaの設定にはViteのconfigを使います。`vite.config.ts`または`vite.config.js`にプラグインとViteのオプションを記述します。`defineConfig`はViteと同じ設定型を提供します。基本的な導入例は[設定ガイド](/ja/docs/guide/configuration)を参照してください。

```ts title="./vite.config.ts"
import { defineConfig, pluginSsg } from "minista"

export default defineConfig({
  plugins: [pluginSsg()],
})
```

## 設定ファイル

`minista.config.*`も後方互換のため利用できます。新しいプロジェクトでは`vite.config.*`を使用してください。複数の設定ファイルを検出すると、`MINISTA_CLI_CONFIG_CONFLICT`で終了します。一つにまとめてください。

`project.json`はサイト情報などをまとめるための利用者のデータファイルであり、ministaが自動的に読み込むconfigではありません。

## 主な設定項目

| 項目                              | 用途                                                               |
| --------------------------------- | ------------------------------------------------------------------ |
| `plugins`                         | ministaや他のViteプラグインを登録                                  |
| `base`                            | アセットの公開ベースパス。ページへの手書きリンクには利用者側で反映 |
| `publicDir`                       | 内容をそのままコピーするディレクトリ。デフォルトは`public`         |
| `server`                          | 開発サーバーのポートなどを設定                                     |
| `build.outDir`                    | 出力ディレクトリ。デフォルトは`dist`                               |
| `build.assetsInlineLimit`         | 小さいアセットのインライン化を制御                                 |
| `build.minify`・`build.cssMinify` | JavaScript・CSSの圧縮を制御                                        |
| `build.rolldownOptions.output`    | ファイル名やコード分割を設定                                       |
| `environments`                    | render／client environmentごとの設定                               |

## Plugins

ministaはv4以降、すべての機能をViteプラグイン化しています。プロジェクトに必要なプラグインを選び、コンフィグの `plugins` に追加してください。

JSX・MDX・Markdownのページ生成と、CSS・JavaScript・画像の参照処理は`pluginSsg()`に含まれます。基本設定は以下だけで利用できます。画像最適化やIslandなどが必要な場合に、対応するプラグインを追加してください。各機能の使い方はプラグインのページを参照してください。

```ts title="./vite.config.ts"
import { defineConfig, pluginSsg } from "minista"

export default defineConfig({
  plugins: [pluginSsg()],
})
```

## 用途別の設定

### 環境ごとの設定

ministaはrender environmentとclient environmentを単一のVite app buildで順にビルドします。多くのVite設定はそのまま両environmentへ適用できます。Node.jsでpageをrenderする側とbrowser向けassetを生成する側で設定を分ける場合は、named environmentの設定かpluginのenvironment-aware hookを使用します。

例として、client environmentだけminifyを無効にします。

```ts title="./vite.config.ts"
import { defineConfig, pluginSsg } from "minista"

export default defineConfig({
  plugins: [pluginSsg()],
  environments: {
    client: {
      build: { minify: false },
    },
  },
})
```

既存の`isSsrBuild`を参照するconfigは、同名pluginでも設定を取り違えないよう、`MINISTA_VITE_APP_CONFIG_LEGACY_ENVIRONMENT`を記録して同一processのcompatibility builderへfallbackします。pluginの名前や順序も変わる場合は`MINISTA_VITE_APP_CONFIG_PLUGIN_MISMATCH`を記録します。新しいconfigでは`environments`、`applyToEnvironment`、`configEnvironment`を使用してください。

`builder.buildApp`はministaがbuild順序を管理するために使用します。application全体の前後処理にはpluginの`buildApp` hookを使用してください。このhookからenvironmentを直接buildすることはできません。

通常のbuild／devはprogrammatic Vite adapterを使用します。programmatic configへ安全に変換できないVite CLI flagを指定した場合だけ外部CLIへfallbackします。

### 画像のインライン化

画像をファイルとして出力したい場合は、`build.assetsInlineLimit` を `0` に設定し、インライン化を無効化する方法があります。

```ts title="./vite.config.ts"
export default {
  build: {
    assetsInlineLimit: 0,
  },
}
```

インライン化を利用したい場合は、インポートパスに`?inline`を付与してください。render environmentでも明示的にインライン化されます。

```tsx title="./src/pages/index.tsx"
import imageUrl from "../assets/image.png?inline"

export default function () {
  return <img src={imageUrl} alt="image" width={76} height={76} />
}
```

### 圧縮を無効にする

圧縮を無効にするには、JavaScriptは`build.minify`、CSSは`build.cssMinify`を`false`にします。HTMLなどの整形は[pluginBeautify](/ja/docs/plugins/beautify)で設定します。

```ts title="./vite.config.ts"
export default { build: { minify: false, cssMinify: false } }
```

### 画像のpreloadを制御する

`pluginSsg`はrenderer出力に含まれるimage preloadを既定で除去します。残したい場合は`pluginSsg({ removeImagePreload: false })`を指定してください。`Head` APIで明示したpreloadは既定でも保持します。詳細は[pluginSsg](/ja/docs/plugins/ssg)を参照してください。

### ファイル名のハッシュを外す

Viteのデフォルト設定では、出力ファイル名にハッシュが付与されます。ハッシュを外すには、以下のプロパティを設定し `[hash]` を削除してください。

- CSS・画像・フォント: `build.rolldownOptions.output.assetFileNames`
- JavaScript（chunk）: `build.rolldownOptions.output.chunkFileNames`
- JavaScript（entry）: `build.rolldownOptions.output.entryFileNames`

これらを設定した場合、出力先はパターン内のパスで決まります。同名ファイルの衝突と公開先のキャッシュ更新方法を確認してください。

```ts title="./vite.config.ts"
export default {
  build: {
    rolldownOptions: {
      output: {
        assetFileNames: "assets/[name][extname]",
        chunkFileNames: "assets/[name].js",
        entryFileNames: "assets/[name].js",
      },
    },
  },
}
```

### アセットの種類ごとに出力先を分ける

Viteのデフォルト設定では、すべてのアセットが同じディレクトリに出力されます。CSS・JavaScript・画像・フォントを別々のディレクトリに出力したい場合は、以下のプロパティを設定してください。

- CSS・画像・フォント: `build.rolldownOptions.output.assetFileNames`
- JavaScript（chunk）: `build.rolldownOptions.output.chunkFileNames`
- JavaScript（entry）: `build.rolldownOptions.output.entryFileNames`

これらを設定した場合、出力先はパターン内のパスで決まります。同名ファイルの衝突と公開先のキャッシュ更新方法を確認してください。

`assetFileNames` は拡張子ごとに分けることができます。

```ts title="./vite.config.ts"
import type { PreRenderedAsset } from "rolldown"

const assetFileNames = (assetInfo: PreRenderedAsset) => {
  const name = assetInfo.name ?? ""
  if (name.endsWith(".css")) {
    return "assets/css/[name][extname]"
  }
  if (/\.(png|jpe?g|gif|bmp|svg|webp|avif)$/.test(name)) {
    return "assets/images/[name][extname]"
  }
  if (/\.(woff2?|ttf|otf|eot)$/.test(name)) {
    return "assets/fonts/[name][extname]"
  }
  return "assets/others/[name][extname]"
}

export default {
  build: {
    rolldownOptions: {
      output: {
        assetFileNames,
        chunkFileNames: "assets/js/[name].js",
        entryFileNames: "assets/js/[name].js",
      },
    },
  },
}
```

### JavaScriptを分割する

JavaScriptから特定のコードを分割したい場合は以下のプロパティを設定してください。

- `build.rolldownOptions.output.codeSplitting.groups`

`node_modules` 内のモジュールを `vendor` という名前でまとめる例。

```ts title="./vite.config.ts"
export default {
  build: {
    rolldownOptions: {
      output: {
        codeSplitting: {
          groups: [{ name: "vendor", test: /\/node_modules\/(?!\.)/ }],
        },
      },
    },
  },
}
```

特定のモジュールごとに分割する例。

```ts title="./vite.config.ts"
export default {
  build: {
    rolldownOptions: {
      output: {
        codeSplitting: {
          groups: [
            { name: "react", test: /\/react(?:-dom)\// },
            { name: "preact", test: /\/preact\// },
            { name: "minista", test: /\/minista\/src|react-icons\// },
          ],
        },
      },
    },
  },
}
```

### クライアント側をPreactへ置き換える

ブラウザ向けReactの代わりにPreactの互換層を使う例です。Reactを使うライブラリとの互換性を確認したうえで採用してください。実際の容量は依存関係やビルド設定によって変わります。render environmentではReactを維持し、client environmentのビルドにだけaliasを適用します。

```sh
npm install preact
npm install --save-dev @vitejs/plugin-react
```

```ts title="./vite.config.ts"
import { defineConfig, pluginSsg, pluginIsland } from "minista"
import react from "@vitejs/plugin-react"
import type { Plugin } from "vite"

const preactAlias = {
  react: "preact/compat",
  "react-dom": "preact/compat",
}

function pluginClientPreactAlias(): Plugin {
  return {
    name: "example:client-preact-alias",
    enforce: "pre",
    apply: "build",
    applyToEnvironment: (environment) =>
      environment.config.consumer === "client",
    resolveId(source, importer, options) {
      for (const [find, replacement] of Object.entries(preactAlias)) {
        if (source !== find && !source.startsWith(`${find}/`)) continue
        return this.resolve(
          `${replacement}${source.slice(find.length)}`,
          importer,
          { ...options, skipSelf: true },
        )
      }
    },
  }
}

export default defineConfig({
  plugins: [pluginSsg(), pluginIsland(), pluginClientPreactAlias(), react()],
})
```

### 出力ディレクトリを空にする

Viteのデフォルト設定では、プロジェクトルート配下にない出力ディレクトリは安全を考えて空にしません。その場所の既存ファイルを削除してよい場合に限り、`build.emptyOutDir`を`true`にします。出力先をソースや他の用途のディレクトリと共有しないでください。

```ts title="./vite.config.ts"
export default { build: { emptyOutDir: true } }
```
