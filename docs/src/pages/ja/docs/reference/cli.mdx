# CLI

ministaのCLIは、開発サーバーの起動、静的ファイルの生成、ページ構成の検査を行います。プロジェクトへインストールしたCLIは、npm scriptsまたは`npx minista`から実行できます。

## コマンド一覧

表の`[root]`は省略可能なプロジェクトルートです。省略すると現在のディレクトリを使います。

| コマンド                           | 内容                                              |
| ---------------------------------- | ------------------------------------------------- |
| `minista [root]`                   | 開発サーバーを起動                                |
| `minista build [root]`             | 静的HTMLとアセットを生成                          |
| `minista preview [root]`           | ビルド済みファイルをローカルで配信                |
| `minista check [root]`             | ページやルートの問題を検査                        |
| `minista inspect [root]`           | Project Graphの概要を表示                         |
| `minista explain <node-id> [root]` | 指定したGraph nodeの関係を表示                    |
| `minista agents [root]`            | インストール済みバージョンのagent向けガイドを表示 |

## 開発・ビルド・プレビュー

```json title="./package.json（scripts）"
{
  "scripts": {
    "dev": "minista",
    "build": "minista build",
    "preview": "minista preview",
    "check": "minista check"
  }
}
```

```sh
npm run dev
npm run build
npm run preview
```

開発サーバーは`Ctrl + C`で停止します。プレビューは既存のビルド結果を確認するためのもので、ソースの変更を自動的にビルドしません。

`minista build`は、render／client environmentを単一のVite app buildで順にビルドします。出力先はデフォルトで`dist/`です。`build.outDir`で変更できます。

プロジェクトルートや開発サーバーのオプションは次のように指定します。

```sh
npx minista ./site --port 3000
npx minista build ./site
npx minista preview ./site --port 4173
```

dev・build・previewではViteのCLIオプションを利用します。通常はministaのVite adapterが処理し、変換できないオプションでは外部のVite CLIへフォールバックする場合があります。

## check：ページ構成を検査する

```sh
npx minista check
npx minista check --json
```

ページmoduleと`getStaticData()`を評価し、ルートやページの問題を検査します。エラーがある場合は終了コードが非0になります。TypeScriptの型チェックや、ビルド結果のブラウザ確認とは別の検査です。

`--json`を付けると機械可読な結果を標準出力へ返します。診断には安定した`code`、`severity`、`message`が含まれ、内容に応じて`hint`、`location`、`phase`、`nodeId`なども付与されます。

## inspect：構成を表示する

```sh
npx minista inspect --json
```

ソースからProject Graphを構築し、ページやルートなどの構成を表示します。通常の`inspect`はページmoduleと`getStaticData()`を実行します。

最後に成功したビルドの情報だけを読みたい場合は、`--manifest`を指定します。

```sh
npx minista inspect --manifest --json
```

この形式ではViteサーバーや利用者のmoduleを起動しません。保存済みmanifestがない場合は自動ビルドせず、`MINISTA_MANIFEST_NOT_FOUND`を返します。ソースを変更した後でも、manifestは次の成功ビルドまで更新されません。

## explain：要素同士の関係を確認する

```sh
npx minista explain "page:route%3Asrc/pages/index.jsx#/" --json
```

指定したGraph nodeの関係を表示します。例のIDは`src/pages/index.jsx`から生成したルートページのものです。対象プロジェクトの`inspect --json`で得たIDを引用符で囲んで渡してください。

通常の`check`・`inspect`と同じく利用者のmoduleを評価するため、データ取得に必要な環境変数などを用意します。

## agents：利用ガイドを取得する

```sh
npx minista agents
npx minista agents --json
npx minista agents --write
```

`agents`はministaに同梱されたガイドを表示します。configやページmoduleを評価しません。

`--json`では、バージョン、ガイドの本文とパス、生成workspaceの場所、manifestと診断ファイルのパス・存在状態を取得できます。表示だけではファイルを作成しません。

`--write`はプロジェクトの`AGENTS.md`へ案内を追加・更新します。既存のminista管理ブロックだけを更新し、それ以外の記述は保持します。`--write --json`で変更結果もJSONとして取得できます。create-ministaは同じ案内を自動生成します。

## 独自オプション

| オプション   | 対象                                    | 内容                           |
| ------------ | --------------------------------------- | ------------------------------ |
| `--json`     | `check`・`inspect`・`explain`・`agents` | 結果をJSON形式で出力           |
| `--manifest` | `inspect`                               | 保存済みmanifestだけを読み取る |
| `--write`    | `agents`                                | `AGENTS.md`へ案内を追加・更新  |

v4の`--oneBuild`は削除されました。指定すると`MINISTA_CLI_OPTION_REMOVED`で終了します。標準の`minista build`を使用してください。

## 生成workspaceと保存される情報

保存先はプロジェクトルート直下の`package.json`の有無で決まります。

| 条件                         | 保存先                   |
| ---------------------------- | ------------------------ |
| ルートに`package.json`がある | `node_modules/.minista/` |
| ルートに`package.json`がない | `.minista/`              |

`check`は検査結果を`diagnostics.json`へ保存します。成功した`build`は構成と出力情報を`manifest.json`へ保存し、ビルドの診断も`diagnostics.json`へ記録します。

manifestは最後の成功ビルド、diagnosticsは直近に記録したcheckまたはbuildの結果なので、同じ実行の情報とは限りません。生成workspaceは手編集せず、サイトの公開物にも含めません。

導入手順は[はじめる](/ja/docs/guide/)、設定ファイルについては[Config](/ja/docs/reference/config)を参照してください。
