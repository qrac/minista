# v4.0.11とv5の性能比較（2026-09-06）

## 結論

- 同一のv5 docsソースによるclean buildは、v5がv4.0.11より39.4%高速だった。
- ソース差がなく外部通信を使わない9個のplaygroundでは、v5が45.4〜50.6%高速だった。fixtureごとの改善率の中央値は49.9%、中央値合計では49.3%短縮された。
- Minista本体とproduction依存の展開後容量は74.91 MiBから50.61 MiBになり、32.4%削減された。この値はpeer dependencyを含まない。
- React、React DOM、Viteを同じpeer dependencyとして含めた導入ツリー全体では、116.72 MiBから87.93 MiBになり、24.7%削減された。
- 現在の特徴を短く示す場合は「buildを最大約50%高速化」「production依存容量を約32%削減」が今回の測定に対応する。

## 比較対象

| 項目 | v4 | v5 |
| --- | --- | --- |
| branch | `main` | `v5` |
| commit | `4dcb545bf1b4398e866f3db43f1a568d082b82bf` | `7768b6c4e57bcb2f7f2d71b0c48ade883d8b0d98` |
| package version | 4.0.11 | 5.0.0 |
| Node.js | v26.2.0 | v26.2.0 |
| architecture | darwin-x64 | darwin-x64 |
| Vite | 8.2.1 | 8.2.2 |
| React | 19.2.8 | 19.2.8 |

Apple Siliconホスト上でNode.jsをdarwin-x64として実行した。各branchを`git archive`で`/tmp`の別ディレクトリへ展開し、それぞれのlockfileから`npm ci --ignore-scripts`した。依存関係のinstall時間はbuild測定に含めていない。

## Build測定方法

- 各build前に対象projectの`dist`、`.minista`、`node_modules/.minista`、`node_modules/.vite`、`node_modules/.vite-temp`を削除した。
- warmupを1回行った後、branchの実行順を交互に変えて測定した。
- docsは5回、playgroundは3回実行し、それぞれ中央値を採用した。
- docsはv5の`docs/src`をmain環境へ複製し、同一contentをbranch固有のconfigと実装でbuildした。リポジトリのmainは変更していない。
- playgroundは`main...v5`でdirectoryに差分がないものから、外部通信を使うFetchとImageを除いた9個を測定した。
- CLI起動を含むwall-clock timeを測定した。

## Production依存容量

`packages/minista/package.json`の`dependencies`と、各packageのproduction／optional dependencyをlockfileどおりに再帰して集計した。peer dependencyはproduction依存容量から除外した。package本体は`npm pack --workspace minista --json`の`unpackedSize`を使用し、依存packageはinstall済みファイルのapparent sizeを使用した。

| 指標 | v4.0.11 | v5 | 変化 |
| --- | ---: | ---: | ---: |
| Minista＋production依存 | 74.91 MiB | 50.61 MiB | -32.4% |
| package数（Ministaを含む） | 229 | 223 | -2.6% |
| Minista tarball | 41.05 KiB | 138.49 KiB | +237.4% |
| Minista unpacked | 179.79 KiB | 600.86 KiB | +234.2% |

容量削減の主因はv4が直接依存していた`@swc/core`と現在のplatform向けnative binaryがv5では不要になったことである。一方、v5のMinista本体はCore、adapter、diagnostics、queryなどの実装追加により大きくなっている。そのため「依存容量の削減」はpackage tarball自体の縮小を意味しない。

利用者が別途導入する共通peer dependencyのReact、React DOM、Viteも含めた場合は次のとおり。Viteのoptional peer dependencyは除外した。

| 指標 | v4.0.11 | v5 | 変化 |
| --- | ---: | ---: | ---: |
| Minista＋production依存＋共通peer依存 | 116.72 MiB | 87.93 MiB | -24.7% |

## 制約

- 数値は単一マシンのwall-clock timeとfilesystem上の容量であり、絶対性能や他platformで同じ比率になることを保証しない。
- Node.jsはApple Silicon上のdarwin-x64実行だった。SWC、Sharp、Rolldownなどのnative package容量はplatformで異なる。
- v4とv5はそれぞれのlockfileを使用したため、Vite、Sharp、SVGOなどのpatch／minor versionが完全には一致しない。
- docsはsource contentだけを統一し、branch固有のconfigを使用した。playgroundはdirectory全体に差分がないfixtureだけを対象にした。
- buildは5回または3回の中央値であり、統計的な性能保証ではない。
- FetchとImageは外部通信の揺らぎを避けるため今回のplayground比較から除外した。Imageの制御測定は[前回の比較](v4-v5-2026-08-14.md#image改善後の制御測定2026-08-15)を参照する。
